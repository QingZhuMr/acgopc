# 移动端适配方案（acgopc → Android / iOS）

> 2026-08-20 立项。本文记录**现有桌面客户端（acgopc）代码结构下**，如何改造以支持移动端。
> 目标：复用现有业务/UI 资产，最小改动跑通 Android + iOS；桌面端体验不得回退。

---

## 1. 现有桌面端架构盘点

### 1.1 项目概况

| 项 | 现状 |
|---|---|
| 项目名 | `acgopc`（本地 `d:\wwwroot\acgopc`，分支 main） |
| 应用名 | 中文「耶熊」/ 英文 `Yeahbear`（`AppConfig.appName / appNameEn`） |
| 版本 | `0.1.3`（`pubspec.yaml`）/ `0.1.4`（`AppConfig.appVersion`） |
| 平台目录 | **仅 `windows/`、`macos/`**，无 `android/`、`ios/` |
| 主要依赖 | `window_manager`、`tray_manager`、`local_notifier`、`sqflite` + `sqflite_common_ffi`、`file_picker`、`silky_scroll`、`web_socket_channel`、`http`、`encrypt/crypto/pointycastle/asn1lib`、`image` |
| UI 规范 | `docs/UI规范.md`（所有页面须遵守，适配后同样适用） |

### 1.2 启动流程（`lib/main.dart`）

```
main()
 ├─ WidgetsFlutterBinding.ensureInitialized()
 ├─ windowManager.ensureInitialized()              ← 桌面专用
 ├─ WindowEffectService.initialize()               ← no-op（实心版），桌面保留
 ├─ AppService.instance.init()                     ← 单实例检测 + 托盘 + 关闭驻留，全桌面专用
 ├─ 设置窗口尺寸 / 最小尺寸 / 标题隐藏（window_manager）
 └─ runApp(AcgoPcApp())
```

`lib/app/app.dart`：`AcgoPcApp`（MaterialApp）→ Splash（检查自动登录）→ 登录 / HomePage。

### 1.3 主框架导航（`lib/pages/home/home_page.dart`）

- **左侧 Finder 风格侧边栏**：宽 `150`（`_effectiveRailWidth`），双端统一；`_buildSidebar` + `_buildMacRail`
- **顶部自绘标题栏**：`TitleBar`（macOS 红黄绿安全区 `kMacTrafficLightWidth` / Windows 窗口按钮）
- **内容区**：`IndexedStack` 保留 6 个 tab（消息 / 广场 / 探索 / 我的 / 通知 / 设置），`_currentIndex` 切换
- **二级页面**：一律走 `_macOverlay`（内容区覆盖层，保留左侧导航栏），**禁止 `Navigator.push` 遮住菜单栏**（2026-08-18 决策）
- `HomePageState.current` 静态实例提供跨文件导航（如 `openChatWithPeer(uid)`）

### 1.5 数据 / 存储层（移动端关键耦合点）

| 模块 | 现状（桌面） | 移动端问题 |
|---|---|---|
| `core/app_config.dart` | `dataDir` = `USERPROFILE`/`HOME` 环境变量取「系统文档目录」+ `appNameEn`；`configDir`（记住密码、忽略更新）、`appDataDir`（device_id/device_key）、`logsDir` | **桌面环境变量在移动端不可用**，需改用 `path_provider`（`getApplicationSupportDirectory`） |
| `core/device_service.dart` | `platform` 已支持 android/ios/mac/win/h5；`device_id`/`device_key` 存 `appDataDir` 文件 | 目录源需换 `path_provider`；逻辑本身可复用 |
| `services/secure_storage.dart` | AES-256-CBC 加密，密钥由「机器标识（主机名+用户名）」派生 | 移动端无主机名/用户名，需改用 `device_id` 或随机密钥持久化 |
| `services/chat_store.dart` | `sqflite` + `sqflite_common_ffi`（桌面 FFI 初始化）；按账号分库 `acgo_chat_<uid>.db` | 移动端用原生 `sqflite`（内置，无需 ffi init）；分库逻辑可复用 |
| `services/ws_service.dart` | Swoole WebSocket，`ws_url` 由服务端 `user/domain` 返回 | 跨平台，基本可复用；注意移动端系统 WebSocket 兼容性 |
| `services/notification_center.dart` + `controllers/system_notifier.dart` | `local_notifier`（Windows Toast）+ 30 秒轮询未读数 | **`local_notifier` 仅桌面**，移动端换 `flutter_local_notifications`；轮询逻辑复用 |
| `services/updater.dart` | 检查更新（桌面下载安装包逻辑） | 移动端分平台：**安卓仍下载安卓安装包（APK）直接安装**；**iOS 依赖 App Store**（只做跳商店/提示升级） |

## 2. 移动端适配总体策略

**原则（2026-08-20 决策）：单代码库（Dart 层）、功能层共享、UI 层按平台分目录。**

> 决策依据：现有代码可复用的绝大部分集中在**功能层**（`core/ services/ controllers/ utils/ models/`）；**前端样式（`pages/ widgets/`）几乎需重新设计与实现**。因此不做"一套 UI 塞 `isDesktop` 分支"，而是移动端前端在 `lib/mobile/` 下独立存放，桌面 `pages/ widgets/` 原样保留（桌面端目录暂不改动）。

1. **功能层共享**：`core/`（配置/API/主题/设备）、`services/`（WS/聊天/通知/更新/存储）、`controllers/`、`utils/`、`models/` 跨平台复用；仅需平台条件分支的点见 1.5 / 1.6。
2. **UI 层分目录**：桌面页面 `lib/pages/`、组件 `lib/widgets/` 保持不动；移动端页面/组件放 `lib/mobile/`（结构见 2.2）。`isDesktop` 仅在入口与共享功能层使用，页面代码不再到处塞平台分支。
3. **桌面逻辑收拢**：所有 `window_manager` / `tray_manager` / 单实例 / 托盘 / `local_notifier` 调用，用 `AppConfig.isDesktop` 包起来；移动端直接跳过。
4. **目录与存储统一**：目录基址从「环境变量文档目录」改为「`path_provider` + 平台判断」，向上兼容桌面（桌面仍走原逻辑）。
5. **交互平移**：hover / 右键（`BubbleMenuOverlay`）→ 长按 / 轻点。
6. **平台目录**：`flutter create --platforms=android,ios .` 生成原生骨架后按需改配置。

### 2.1 建议的兼容常量（`core/app_config.dart` 新增）

```dart
/// 是否桌面端（Windows / macOS）
static bool get isDesktop =>
    !kIsWeb && (Platform.isWindows || Platform.isMacOS);

/// 移动端数据目录（path_provider 应用支持目录），桌面仍用原文档目录
static String get dataDir => isDesktop ? _documentsDir() : _appSupportDir();
```

### 2.2 目录结构：`lib/mobile/` 移动端前端（2026-08-20 决策）

```text
lib/
├─ main.dart               # 入口（按 AppConfig.isDesktop 分流：桌面 AcgoPcApp / 移动 MobileApp）
├─ app/                    # 共享：AcgoPcApp（MaterialApp）
├─ core/                   # 共享：app_config / api_client / app_theme / device_service
├─ services/               # 共享：ws_service / chat_* / notification_center / updater / secure_storage …
├─ controllers/            # 共享：time_util（system_notifier 仅桌面，移动端用极光/本地通知替代）
├─ utils/                  # 共享：time_format / text_sanitize / net_image / image_download …
├─ models/                 # 共享：数据模型
├─ widgets/                # 共享通用组件（无平台依赖：cached_avatar / user_avatar / emoji_data / silky_scroll）
├─ pages/                  # 桌面端页面（现状保留，移动端不使用）
└─ mobile/                 # ★ 移动端前端（新建）
   ├─ mobile_app.dart      # 移动端根组件（主题/路由）
   ├─ pages/               # 移动端页面：home / message / planet / profile / settings / post_detail / publish / notification / login / register / splash …
   ├─ widgets/             # 移动端组件：移动端卡片/弹层/长按菜单…（底部标签栏用插件 GlassTabBar.bottom，内联 home_page.dart）
   └─ theme/               # 移动端主题适配（系统字体、字号、明暗）
```

**边界约定：**

- 移动端页面**只 import** `core/ services/ controllers/ utils/ models/` 与 `mobile/widgets/`，**不 import** `pages/`、`widgets/` 下的桌面实现（避免把桌面 UI 拖进移动端产物）。
- 通用、无平台依赖的组件（`cached_avatar` / `user_avatar` / `emoji_data` / `silky_scroll`）留在 `widgets/` 共享；平台相关交互组件（`title_bar` / `bubble_menu` / `pick_images` / `planet_globe`）移动端在 `mobile/widgets/` 重写或包移动端手势适配层。
- 新增功能遵循：桌面页面 → `pages/`，移动端页面 → `mobile/pages/`；**同一业务逻辑不双写**，只进 `services/ core/`。

## 3. 分模块适配明细

### 3.1 平台骨架与构建配置

1. `flutter create --platforms=android,ios --org com.acgo .`（先生成骨架，不覆盖现有 `lib/`）。
2. **Android**：
   - `android/app/build.gradle`：`applicationId`（如 `com.acgo.yeahbear`）、`minSdkVersion`（≥21，`sqflite` 需要）、`targetSdk`。
   - `AndroidManifest.xml`：`INTERNET` 权限；`usesCleartextTraffic="true"`（开发期 http，生产必须 https）；深链可选。
3. **iOS**：
   - `Info.plist`：`NSPhotoLibraryUsageDescription`（选图）、`NSUserNotificationUsageDescription`；ATS 白名单（生产 https 可关闭例外）。
4. 应用图标 / 启动图：Android `mipmap`、iOS `Assets.xcassets`（可后续补）。

### 3.2 依赖调整（`pubspec.yaml`）

| 依赖 | 现状 | 移动端处理 |
|---|---|---|
| `window_manager` | ^0.3.9 | 保留（移动端编译不引入调用即可，包本身支持多平台 stub），**所有调用点包 `isDesktop`** |
| `tray_manager` | ^0.2.0 | 同上，桌面专用，移动端不调用 |
| `local_notifier` | ^0.1.5 | **仅 Windows/macOS 有效**；移动端换 `flutter_local_notifications` |
| `sqflite_common_ffi` | ^2.3.3 | 移动端**不调用** `sqfliteFfiInit`，用原生 `sqflite`（Windows/Linux 才需要 ffi） |
| `file_picker` | ^8.0.0 | 移动端可用；`pickImages` 中 macOS 分支保留，移动端走 file_picker 或换 `image_picker` |
| 新增 `path_provider` | — | 移动端数据目录 |
| 新增 `flutter_local_notifications` | — | 移动端系统通知（替换 `local_notifier`） |
| `crop_image_pro` | ^1.2.0 | **已弃用**，头像裁剪用 main.dart 自绘控件（`_AvatarCropEditor`），勿再引入 |

> 若担心桌面依赖在 Android/iOS 编译报错：这些包普遍有平台守卫，不会导致编译失败；仅运行时行为在移动端无效，故**关键在调用点加 `isDesktop` 判断**，而非删依赖。

### 3.3 启动流程改造（`lib/main.dart`）

**2026-08-20 已落地**：入口分流 = `AppConfig.isMobile || MOBILE_PREVIEW` 走 `MobileApp`（移动端 UI），否则走桌面 `AcgoPcApp`。

```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  // 手机预览模式：--dart-define=MOBILE_PREVIEW=true
  // 在 Windows 桌面以手机尺寸窗口（390×844）运行移动端 UI，无需 Android/iOS 模拟器
  const bool mobilePreview = bool.fromEnvironment('MOBILE_PREVIEW');
  if (AppConfig.isMobile || mobilePreview) {
    if (mobilePreview) { /* 手机尺寸窗口（window_manager） */ }
    runApp(const MobileApp());   // mobile/mobile_app.dart
    return;
  }
  if (AppConfig.isDesktop) {
    await windowManager.ensureInitialized();
    await WindowEffectService.initialize();
    await AppService.instance.init();   // 单实例/托盘/关闭驻留
    // 设置窗口尺寸/最小尺寸/标题隐藏（window_manager）
  }
  runApp(const AcgoPcApp());
}
```

- `lib/services/app_service.dart` 内的单实例检测、托盘、关闭驻留、唤起窗口全部包 `isDesktop`，移动端跳过。
- 移动端无需「最小化到托盘/关闭驻留」，点击系统返回键默认退到后台（Android 默认行为）。
- **预览方式**：电脑（Windows）上运行 `flutter run -d windows --dart-define=MOBILE_PREVIEW=true`，即弹出 390×844 手机尺寸窗口显示移动端 UI（标题栏保留，可拖动/关闭）；后续生成 android/ios 骨架后可用模拟器/真机。

### 3.4 数据目录 / 存储改造

**`core/app_config.dart`：**

```dart
import 'package:path_provider/path_provider.dart';

static String _appSupportDir() {
  final dir = getApplicationSupportDirectory(); // Future，需改为 async 初始化
  ...
}
```

> 注意 `dataDir` 目前是同步 getter 且多处同步读（`DeviceService`、`SecureStorage`）。移动端 `path_provider` 是异步 API。**建议**：
> 1. 在 `main()` 早期 `await` 一次初始化，缓存 `static String? _dataDir`；
> 2. 保持现有同步 getter 签名，从缓存取值；
> 3. 桌面端仍走 `_documentsDir()` 同步逻辑（不受影响）。

**`services/secure_storage.dart`：**
- 密钥派生改：`kIsWeb/isDesktop ? 机器标识 : device_id`（`DeviceService.getDeviceId()` 已有，跨平台）。

**`services/chat_store.dart`：**
- 移动端初始化：仅桌面调 `databaseFactory = databaseFactoryFfi`；移动端用 `sqflite` 默认 factory。

### 3.5 主框架导航改造（移动端独立：`lib/mobile/pages/home_page.dart`）

> 按 2.2 目录决策：**移动端主框架不再改桌面 `pages/home/home_page.dart`**，而是新建 `lib/mobile/pages/home_page.dart`（MobileApp 根路由），桌面 `home_page.dart` 原样保留。

| 桌面（现状 `pages/home/home_page.dart`） | 移动端（`mobile/pages/home_page.dart`） |
|---|---|
| 左侧侧边栏宽 150 + 图标+文字 | 底部 `NavigationBar`（5~6 个 tab），**iOS 26 液态玻璃风格（B 方案：`liquid_glass_widgets` shader 玻璃）**，详见下方「底部标签栏（液态玻璃）」 |
| 内容区 `IndexedStack` | 改 `PageView`（横向滑动切换 tab）+ 各 tab 页 `AutomaticKeepAliveClientMixin` 保状态（2026-08-20 更新） |
| `_macOverlay` 内容区覆盖 | **改 `Navigator.push` 全屏页**（移动端无侧边栏概念，全屏合理；`openChatWithPeer` 等改为 push） |
| `TitleBar` 自绘标题栏 | 隐藏；用 `Scaffold.appBar` 或页面内 `SecondaryTitleBar` |

**底部标签栏（液态玻璃，B 方案）实现要点（`home_page.dart` 内联 `GlassTabBar.bottom`）：**

- **玻璃**：用三方库 **`liquid_glass_widgets`**（^0.30.1，shader 真液态玻璃，2026-08-20 决策：放开「不引三方库」，用户确认非硬标准；2026-08-20 恢复启用，完全照插件官方示例 `example/example.dart` 写法，只换 tab 入口）；组件 `GlassTabBar.bottom` 注入 `GlassScaffold.bottomBar`，`GlassTab(icon: Icon(...), label: ...)` 直接传 Icon（原 `mobile/widgets/mobile_bottom_nav.dart` 封装已删除）。**选中态**：`selectedIconColor` / `selectedLabelColor` = 主题蓝 `kPrimary`（0xFF0A84FF，用户 2026-08-20 要求），未选中走插件默认。**渲染质量**：`quality: GlassQuality.premium`（高精管线，2026-08-20 反馈圆角锯齿后采用）。
- **滑动切换（2026-08-20 定案）**：内容区 `PageView` 横向滑动切 tab（`BouncingScrollPhysics` iOS 回弹），各 tab 页 `AutomaticKeepAliveClientMixin` 保状态；`GlassTabBar` 受控组件：`selectedIndex` 绑 `TabController.index`、`onTabSelected` → `animateTo`、`PageView.onPageChanged` 同步选中。滑动/点击动画走库内置 **Liquid Morph**（果冻物理过冲）。
- **深色模式**：`GlassTabBar.bottom` 内容感知自适应；`MaterialApp` 需 `LiquidGlassWidgets.wrap(..., brightnessResolver: Theme.maybeBrightnessOf)`，入口 `main()` 先 `LiquidGlassWidgets.initialize()`。
- **黄色双下划线防护**：`GlassScaffold` 底层为 `CupertinoPageScaffold`（无 Material 上下文），body **和 bottomBar（`GlassTabBar`）**都必须包透明 `Material`，否则 Text 渲染黄色双下划线伪影（2026-08-20 实测：只包 body 时 tab label 仍会有；当初弃用根因，非 shader 异常）。
- 安全区：`GlassTabBar.bottom` 自带安全区适配，玻璃容器悬浮在内容之上。
- 回退：低端设备掉帧时退回自绘（`ClipRRect` + `BackdropFilter` 模糊 + 半透明渐变 + 高光描边），封装层整体替换。

**断点建议：** 移动端为主体的独立页面，不再依赖桌面 `LayoutBuilder` 断点；桌面/移动由入口 `main.dart` 分流（2.2），各页面内部仅按宽度微调（如瀑布流列数）。

### 3.6 消息页双栏 → 单栏（`message_page.dart`）

### 3.9.1 iOS 26 适配考量

- **Liquid Glass（液态玻璃）**（2026-08-20 决策，后更新为**全页面 + 放开三方库**）：**移动端所有页面内容均模仿 iOS 26 液态玻璃风格，实现走 B 方案（Flutter 层实现：一级浮层优先三方库 `liquid_glass_widgets` shader 真玻璃，其余自绘兜底；不写原生壳；Android / iOS 统一）**。分级玻璃：一级浮层（导航栏/标签栏/搜索栏/底部 sheet/弹窗）真玻璃（shader 优先，自绘兜底 sigma 10~12），二级浮层（卡片/分组列表/输入框/按钮）弱玻璃或半透明底，滚动列表项不套 `BackdropFilter`；每屏实例 ≤ 3。权威规格见 `docs/UI规范.md` 第 11 章、执行要点见 `docs/移动端UI规范.md` §1.1。标签栏实现要点见 3.5「底部标签栏（液态玻璃）」。
- **新版通知中心**：通知横幅/分组由系统统一接管，与 `flutter_local_notifications` / 极光推送不冲突；注意自定义通知内容长度与分组策略按系统规范控制。
- **自适应字号/图标**：iOS 26 强化可访问性（动态字体、高对比度），页面用系统字号（`isDesktop ? 'Segoe UI Variable' : null`）即自动适配。
- 结论：**iOS 26 无阻断性适配问题**；移动端全页面做液态玻璃化（B 方案：一级浮层优先 `liquid_glass_widgets` shader 玻璃 + 分级玻璃控制性能），详见 `docs/UI规范.md` 第 11 章。

### 3.10 其他

- **字体**：`app_theme.dart` 的 `fontFamily` 改为条件：`isDesktop ? 'Segoe UI Variable' : null`（null 用系统默认），fallback 列表在移动端删除微软雅黑。移动端主题适配放 `mobile/theme/`，取色仍走 `core/app_theme.dart` 常量（`kPrimary` 等），不硬编码颜色。
- **安全区**：移动端所有页面包 `SafeArea`（刘海/底部手势条）。
- **更新**（`updater.dart`）：移动端分平台——**安卓保留「检查更新下载安装包」**（下载 APK 后走系统安装器安装）；**iOS 依赖 App Store**，只检测版本并跳 `itms-apps://` 应用商店页或提示前往商店升级。
- **调试网络**：本地开发手机连电脑需 `apiBase`/`ws_url` 指向局域网 IP（服务端 `user/domain` 返回的 `ws_url` 须是移动端可达地址——已有约束「不能返回 0.0.0.0」，扩展为「不能返回 127.0.0.1 给手机」）。

## 5. 风险与注意事项

1. **桌面不回归**：桌面 `pages/ widgets/` 文件**不做移动端改造**（移动端页面一律进 `lib/mobile/`），因此桌面天然不回归；共享功能层（`core/ services/ utils/`）的改动必须 `isDesktop` 分支保护，改完桌面跑一遍。
2. **目录同步 getter 与异步 path_provider**：这是移动端改造最大隐患，必须先做「启动时初始化缓存」再放开其他改造。
3. **`sqflite_common_ffi` 依赖**：移动端不要调 `sqfliteFfiInit`，否则可能报 `PlatformException`（sqlite3 库缺失）。
4. **文档联动**：移动端 UI 改动同样需同步 `docs/UI规范.md`；新增/修改接口同步 `docs/API接口文档.md`。
5. **后续新增页面约束**：桌面新页面 → `pages/`，移动端新页面 → `mobile/pages/`；共享业务逻辑只进 `services/ core/`，禁止双写；移动端页面不得依赖桌面专用 API。
